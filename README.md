# 動画変換ツール（video-converter）

iPhone の画面録画を、互換性の高い **H.264（AVC）形式の MP4** に変換する Web アプリです。

iPhone の画面録画は、拡張子が `.mp4` でも映像が HEVC（H.265）で圧縮されていることがあり、
Windows・Ubuntu の一部の環境や Claude Code などのツールで扱えない場合があります。
このツールはそれを、どこでも再生・処理しやすい H.264 + AAC の MP4 に変換します。

- 変換は **ブラウザの中（利用者の端末の中）だけ** で行います。動画はどこにもアップロードされません。
- サーバーやデータベースは不要です。GitHub Pages にそのまま置ける静的サイトです。
- 変換には [FFmpeg.wasm](https://github.com/ffmpegwasm/ffmpeg.wasm)（FFmpeg を WebAssembly にしたもの）を使い、Web Worker の中で動かすので、変換中も画面は固まりません。

## 使い方

1. 「動画を選ぶ」を押すか、動画を画面にドラッグ＆ドロップします（iPhone ではファイル選択で「写真ライブラリ」から選べます）。
2. ファイル名・サイズ・長さ・解像度・映像と音声の形式が表示されます。間違えたときは「別の動画を選ぶ」「選択を解除」で選び直せます。
3. 必要なら設定を変えます（ふつうはそのままで大丈夫です）。
4. 「変換開始」を押します。進み具合（%）・経過時間・残り時間の目安が表示され、途中でキャンセルもできます。
5. 終わったらプレビューで確認し、「ダウンロード」で保存します。ファイル名は `元の名前_H264.mp4` です。変換前後のサイズも比べられます。

### 変換の設定

| 設定 | 選択肢（太字が初期値） | 内容 |
| --- | --- | --- |
| 画質 | 高画質 / **標準** / 小さめ | x264 の CRF 19 / **23** / 28 |
| 変換の速さ（詳細設定） | **標準** / 速い | x264 の preset `veryfast` / `superfast` |
| 解像度（詳細設定） | **元のまま** / 長い辺 1920px まで / 1280px まで | 縮小時も縦横比は保持（Lanczos） |
| なめらかさ（詳細設定） | **元のまま** / 1秒30コマまで | 30fps を超える動画だけ `fps=30` |
| 音声（詳細設定） | **残す** / 消す | 残す場合は AAC（元が AAC ならそのまま） |
| すでに H.264 の動画 | **画質そのまま MP4 に整える** / 変換し直す | 前者は映像を作り直さない（`-c:v copy`） |

初期値は、画面の文字がはっきり読めることと、変換時間・ファイルサイズのバランスで選んでいます
（886×1920・60fps・文字がスクロールし続ける 10 秒の動画での実測は下の「性能の目安」を参照）。

### 変換の中身

HEVC などの動画は、おおむね次の ffmpeg コマンドと同じ処理になります（`src/ffmpeg-args.js`）。

```sh
ffmpeg -i input.mp4 -map 0:<映像> -map 0:<音声…> -map_metadata -1 -map_chapters -1 \
  -c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p -fps_mode vfr \
  -c:a copy \
  -movflags +faststart -f mp4 output_H264.mp4
```

音声が AAC 以外のときは `-c:a copy` の代わりに `-c:a aac -b:a 128k`（3ch 以上なら `-ac 2` も）になります。

- **映像**：H.264（libx264）、ピクセル形式 `yuv420p`（8bit 4:2:0。ほぼすべての再生環境に対応）。
- **解像度・縦横比**：そのまま。回転情報（縦向き撮影など）は映像に反映します。`yuv420p` は縦横が偶数である必要があるため、奇数のときだけ端の 1px を切り落とします。
- **フレームレート**：画面録画は可変フレームレート（画面が止まっている間はコマが少ない）なので、コマを水増しせず元のタイミングのまま保存します（`-fps_mode vfr`）。
- **音声**：AAC で保存。もともと AAC なら再圧縮せずコピーします。音声のない動画もそのまま変換できます。複数の音声トラックはすべて残します。
- **すでに H.264（8bit 4:2:0）の動画**：初期設定では映像を作り直さず MP4 に入れ直すだけなので、画質は落ちず数秒で終わります。10bit や 4:4:4 の H.264 は再生できない環境があるため変換し直します。
- **メタデータ**：撮影場所などのファイル情報は出力に含めません。
- 変換後、出力ファイルを ffprobe で調べ、実際の形式（H.264・yuv420p・AAC など）を画面に表示します。

## 技術構成

- HTML / CSS / JavaScript（ES モジュール）。フレームワークやバンドラーは使っていません。
- [@ffmpeg/ffmpeg](https://www.npmjs.com/package/@ffmpeg/ffmpeg) **0.12.15**（Web Worker で FFmpeg を動かす JS ライブラリ）
- [@ffmpeg/core](https://www.npmjs.com/package/@ffmpeg/core) **0.12.10**（FFmpeg 5.1.4 の WebAssembly 版・**シングルスレッド版**）
  - マルチスレッド版（`@ffmpeg/core-mt`）は SharedArrayBuffer のために COOP/COEP ヘッダーが必要ですが、GitHub Pages ではそのヘッダーを設定できません。そのため、特別な設定なしで動くシングルスレッド版を使っています。
- ライブラリのバージョンは `package.json` で固定（`^` なし）し、`package-lock.json` で整合性ハッシュも固定しています。
- ライブラリは CDN から読み込まず、ビルド時に `node_modules` から `dist/vendor/` にコピーして、**同じサイトから配信** します。
- すべての URL は相対パスなので、`https://<ユーザー名>.github.io/<リポジトリ名>/` のようなサブパスでも、そのままで動きます。

### 処理の流れと工夫

- **画面を止めない**：FFmpeg は Web Worker の中で動きます。メインスレッドは画面の更新だけを行います。
- **メモリを節約**：選んだ動画は Emscripten の WORKERFS でマウントし、FFmpeg が必要な部分だけを読みます（動画全体をメモリにコピーしません）。
- **後片付け**：変換が終わったら（成功・失敗・キャンセルのいずれでも）作業ファイルを消し、Worker を終了して WebAssembly のメモリを返します。前の結果の Blob URL も、新しい動画を選んだときに解放します。
- **キャンセル**：Worker を終了させて止めます。次の変換では FFmpeg を読み込み直します（ダウンロード済みのデータを使うので短時間です）。
- **ダウンロードは 1 回だけ**：FFmpeg 本体（`ffmpeg-core.wasm`・約 31MB）は、ページを開いて最初に使うときに 1 回だけダウンロードし（進み具合を表示）、ページを開いている間は Blob として持っておきます。シークレットウィンドウのように大きなファイルをキャッシュしないブラウザでも、変換のたびに再ダウンロードしません。
- **二重実行の防止**：変換中は「変換開始」・ファイル選択・設定を操作できなくしています。
- **中断の防止**：変換中にページを閉じようとすると確認を出し、対応ブラウザでは画面の自動ロックを止めます（Screen Wake Lock API）。
- **通信の制限**：ページに Content Security Policy を設定し、このサイト以外との通信をブラウザ側で禁止しています。

## ローカルでの動作確認

Node.js 22 以上が必要です。

```sh
npm ci          # 依存ライブラリのインストール（package-lock.json のとおり）
npm start       # dist/ を作って http://localhost:8080/video-converter/ で配信
```

ブラウザで <http://localhost:8080/video-converter/> を開きます。
GitHub Pages と同じくサブパスで配信するので、サブパスで読み込みに失敗しないかもここで確認できます
（ポートやパスは `node scripts/serve.mjs --port 3000 --base /my-repo/` のように変えられます）。

`index.html` をファイルとして直接開く（`file://`）と、Web Worker や WebAssembly が動かないため変換できません。必ずサーバー経由で開いてください。

### テスト

```sh
npm test        # 単体テスト（変換の引数・ffprobe の読み取り・エラー判定・表示の整形）
npm run e2e     # ビルドして Playwright で画面テスト
```

`npm run e2e` には、ネイティブの `ffmpeg` / `ffprobe`（libx264・libx265 入り。Ubuntu なら `sudo apt install ffmpeg`）が必要です。
iPhone の画面録画をまねたテスト動画（HEVC・`hvc1`・可変フレームレート・AAC・回転情報付きなど）を `scripts/make-fixtures.sh` で作り、
変換結果を ffprobe で検査します。インストール済みの Chromium を使う場合は `CHROMIUM_PATH=/path/to/chromium npm run e2e` とします。

画面テストで確かめていること：

- `/video-converter/` のサブパスで、ページ・FFmpeg・ライセンス文書が読み込めること（404 がないこと）と、このサイト以外への通信がないこと
- HEVC + AAC の MP4 → H.264（yuv420p）+ AAC の MP4。解像度・長さ・フレーム数（可変フレームレート）が保たれ、ネイティブの ffmpeg で最後までデコードできること
- 音声なし・回転情報付きの HEVC（MOV）→ 回転を反映した H.264
- すでに H.264 の動画 → 再圧縮なしで MP4 に入れ直し（フレーム数・ビットレートが元と同じ）／設定で変換し直し
- 4:4:4・奇数サイズの H.264 → yuv420p・偶数サイズ
- 変換中の進捗（%）表示、変換中も画面が固まらないこと（メインスレッドのタイマーが 200ms 以上止まらない）
- 変換のキャンセルと、その後の再変換（FFmpeg のダウンロードはページで 1 回だけ）
- 動画以外・壊れた動画・映像のない MP4・未選択での変換開始 → 原因と対処方法の表示
- 選択の解除・変更、ドラッグ＆ドロップ
- FFmpeg の読み込み失敗 → エラー表示と「もう一度試す」での復帰
- スマートフォン幅で横にはみ出さないこと

## GitHub Pages での公開

1. このリポジトリを GitHub に push します。
2. GitHub のリポジトリ画面で **Settings → Pages → Build and deployment → Source** を **「GitHub Actions」** にします。
3. `main` ブランチに push すると、`.github/workflows/pages.yml` が単体テスト → `npm run build` → `dist/` の公開を行います（Actions タブから手動実行もできます）。
4. `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます。

補足：

- 公開されるのは `dist/` の中身（約 31MB。ほとんどが `ffmpeg-core.wasm`）です。GitHub Pages では `.wasm` が正しい MIME タイプ（`application/wasm`）で配信されます。
- GitHub Pages の初期設定では、公開できるのはリポジトリのデフォルトブランチ（通常 `main`）からです。空のリポジトリに最初に push したブランチがデフォルトブランチになるため、必要に応じて Settings → General で `main` をデフォルトにしてください。
- 公開先のパスはリポジトリ名で決まりますが、アプリ側の設定変更は不要です（すべて相対パスのため）。

## プライバシー

- 動画はアップロードしません。変換はすべて利用者のブラウザの中で行います。
- 通信は、ページと FFmpeg（約 31MB）を公開サイト（GitHub Pages）から読み込むときだけです。外部の CDN・アクセス解析・広告は使っていません。
- Content Security Policy で、このサイト以外との通信をブラウザ側で禁止しています。
- 動画の内容・ファイル名・映像や音声を分析・収集する機能はありません。FFmpeg のログは画面の「詳細ログ」に表示するだけで、どこにも送りません（ログの中のファイル名は `input.mp4` などに置き換わっています）。
- 出力には撮影場所などのメタデータを含めません。
- GitHub Pages のサーバーには、一般的な Web サイトと同じくアクセス記録（IP アドレスなど）が残る場合があります。

## 性能の目安

この開発環境（クラウド上の Linux、ヘッドレス Chromium）で、886×1920・60fps・文字が 10 秒間スクロールし続ける HEVC 動画（5.1MB）を変換した実測値です。
動きの少ない画面録画はこれより速く終わります。実際の速さは端末によって大きく変わります。

| 設定 | かかった時間 | 出力サイズ |
| --- | --- | --- |
| 標準（veryfast・CRF 23） | 73 秒 | 2.5MB |
| 速い（superfast・CRF 23） | 49 秒 | 7.1MB |
| 小さめ（veryfast・CRF 28） | 66 秒 | 0.9MB |
| 参考：veryfast・CRF 20（高画質は CRF 19 なので、これより少し大きくなります） | 79 秒 | 4.8MB |
| 標準 + 1秒30コマまで | 47 秒 | 4.1MB |
| 標準 + 長い辺 1280px まで | 48 秒 | 1.9MB |

参考：`ultrafast` は 36MB、`faster` は 121 秒で 2.4MB、`medium` は 156 秒で 3.0MB だったため、選択肢から外しています。

## 制限事項・未検証の事項

正直に書いておきます。

- **実際の iPhone の画面録画ファイルでは試していません。** iPhone の画面録画の特徴（HEVC・`hvc1`・可変フレームレート・AAC・回転情報）をまねたテスト動画で確認しています。
- **自動テストは Linux 上の Chromium（ヘッドレス）だけ** です。iPhone / Mac の Safari、Firefox、Windows の Chrome / Edge では試していません。特に iPhone の Safari での、メモリ上限・WORKERFS・ダウンロード・共有の動きは未確認です。
- テストに使った Chromium は H.264 を再生できないビルドのため、**画面上のプレビュー再生は確認できていません**（変換結果がネイティブの ffmpeg で最後までデコードできることは確認済み）。プレビューできないブラウザでは、その旨を画面に表示します。
- **実際の GitHub Pages への公開はまだ行っていません。** GitHub Pages と同じ条件（サブパス配信・COOP/COEP なし）のローカルサーバーで確認しています。
- メモリ不足とダウンロード失敗は、エラー表示と原因の判定（単体テスト）を実装していますが、実際にその状態を起こしての確認はしていません。
- 「2GB まで」「スマートフォンは 500MB 程度まで」は目安で、実測ではありません。ブラウザがメモリ不足でタブごと再読み込みした場合は、ページ側では検知できません。
- シングルスレッドで動くため、変換はネイティブの FFmpeg より大幅に遅くなります。
- HDR（iPhone のカメラで撮った HLG / Dolby Vision など）の動画は、色の変換（トーンマッピング）をしないため、色が薄く見えることがあります（画面に注意を表示します）。
- 「空間オーディオ」など FFmpeg が対応していない音声の動画は、音声を消すよう案内します（実ファイルでは未確認）。
- 「共有・写真に保存」ボタンは、ファイルの共有に対応したブラウザ（主にスマートフォン）でだけ表示されます（動作は未確認）。
